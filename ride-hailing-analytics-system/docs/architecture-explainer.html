五、关键考点 + 与 legal-doc-rag 对照

    

      
① 安全双防线
validators.validate_question 拦注入型输入；sql_executor.validate_sql 拦危险 SQL（SELECT 白名单 + INSERT/DROP/... 黑名单）。两层各管一段，配合才完整。另：jwt_handler.SECRET_KEY 硬编码是生产隐患，应从环境变量读。

      
② 多 Agent 不是另起炉灶
多 Agent 把单 Agent 的 generate_sql + run_sql + interpret 拆给三 Agent，靠 SharedMemory 黑板接力。底层 execute_sql 与 validate_sql 完全共用。多 Agent 多了可观测轨迹 agent_trace 和职责分离。

      
③ 与 legal-doc-rag 对照
legal-doc-rag = RAG（向量检索 + 生成）；ride-hailing = NL2SQL（LLM 写 SQL 查真库 + 生成洞察）。一个按 tenant_id 物理隔离 Chroma，一个单 SQLite + JWT 鉴权。两者都以「用户问题」为入口、LLM 为编排核心。
