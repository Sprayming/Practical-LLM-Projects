# 面试追问坑清单（一页速查）

> 配合 `student.md` 第六节使用。面试前 5 分钟快速过一遍，核心原则：**诚实 + 有闭环 + 拔高成方法论**。
> 6 个坑的完整复盘见 `README.md`『踩坑记录与复盘』。

| # | 坑 | 面试官会怎么问 | 一句话标准答 | 拔高点 |
|---|----|--------------|-------------|--------|
| 1 | Schema 列名漂移 | "44 测试都过，真能跑吗？" | 建库改名没同步代码，4 模块全 `no such column`；改 schema 要全局检索 + 必须有真实 DB 集成测试 | schema 治理、测试金字塔 |
| 2 | mock 测试盲区 | "测试能信吗？" | 44 测试全 mock DB，没连过真库；补了端到端冒烟 + 建议内存 SQLite 集成测试 | mock 测逻辑、集成测契约 |
| 3 | .env 不进版本库 | "密钥怎么管？新机器第一步？" | `.env` 被 gitignore（正确），每台 `cp .env.example .env` 填 key；无 key 非 LLM 功能降级可用 | 安全意识 + 部署 runbook |
| 4 | 多 Agent 名实不符 | "Agent 怎么并发/通信？" | 早期是固定顺序流水线，v0.5 才真落地 Orchestrator+3 Agent+共享黑板；如实说演进 | 技术叙事与架构一致，不夸大 |
| 5 | README 表格错位 | "细节也管？" | CJK+emoji 宽度不一，改等宽代码块 + `✓/✗` 固定符号 | 文档即产品 |
| 6 | 旧进程占端口 | "怎么保证测的是最新代码？" | 曾误测旧 uvicorn 实例；现在验证前先查端口强杀残留再复验 | 环境干净 = 测试可信前提 |

## 讲坑四原则
1. **不回避**：主动说"实测真踩过 X"，比被问住强 10 倍。
2. **有闭环**：怎么发现 → 怎么修 → 以后怎么避免。
3. **拔高**：升华成方法论（测试金字塔 / schema 治理 / 密钥管理 / 文档即产品）。
4. **关联业务**：坑 1/2 证明你是"会真跑真测"的工程师，区别于只写 demo 的人。
